# 输入输出、运行合同与科学边界

## 1. 职责边界

本 Skill 负责把已经核对来源的蛋白质序列和已经过化学结构审查的配体转换为
官方兼容的 Protenix 输入，在独立 GPU Runtime 中调用官方 CLI，并验证预测
结构、链、配体和置信度文件。

工作流分工：

```text
宿主 Agent + dataPro_search
论文发现与候选证据
        ↓
resolve-chemical-identities
名称/标识符 → 唯一候选或人工复核
        ↓
standardize-chemical-structures
reported/standardized/parent、盐型、立体化学、电荷和状态
        ↓
predict-complex-structures
官方输入 → Protenix GPU → 结构/置信度校验 → 专家复核包
```

本 Skill 不实现 DataPro MCP Client，不读取 Agent Plan Key，不复制已有化学
Skill 的身份解析或结构标准化算法，也不把 Protenix 输出解释为实验结论。

## 2. 依赖与运行环境

轻量准备和验证环境固定：

| 依赖 | 版本 | 用途 | 许可证 |
|---|---|---|---|
| RDKit | `2025.9.2` | 从已审查的具体配体结构生成重原子/元素校验口径 | BSD-3-Clause |
| Gemmi | `0.6.7` | 独立解析和检查 CIF/mmCIF | MPL-2.0 |

Protenix 独立 Runtime：

- Python `>=3.11`；
- NVIDIA GPU 与匹配的 CUDA/PyTorch；
- 官方 `protenix` CLI；
- 所选模型权重；
- 启用模板或 RNA MSA 时还需要 Kalign、HMMER 及相应数据库。

Protenix 代码和模型参数由官方声明为 Apache-2.0。本 Skill 只调用其 CLI，
不打包模型代码、权重或大型数据库。

首版模型白名单：

```text
protenix-v2
protenix_base_default_v1.0.0
protenix_base_20250630_v1.0.0
protenix_base_default_v0.5.0
protenix_base_constraint_v0.5.0
protenix_mini_default_v0.5.0
protenix_tiny_default_v0.5.0
```

需要额外 ESM/ISM 权重的模型首版失败关闭。模板和 RNA MSA 只允许用于官方
声明支持的 `protenix-v2` 和两个 v1.0.0 base 模型。

## 3. 外部请求合同

请求顶层示例：

```json
{
  "schema_version": "1.0.0",
  "job_id": "complex-001",
  "research_question": "为已知蛋白质与配体组合生成可复核结构假设",
  "proteins": [
    {
      "chain_id": "A",
      "sequence": "MKT...",
      "organism": "Homo sapiens",
      "source": {
        "database": "UniProt",
        "identifier": "P12345",
        "url": "https://www.uniprot.org/uniprotkb/P12345"
      },
      "modifications": []
    }
  ],
  "reference_structures": [
    {
      "path": "reference.cif",
      "sha256": "<64 hex>",
      "source": "RCSB PDB",
      "identifier": "1ABC"
    }
  ],
  "ligand": {
    "chain_id": "L",
    "reported_name": "example ligand",
    "source": {
      "database": "ChEMBL",
      "identifier": "CHEMBL1"
    },
    "identity_artifact": "identity.json",
    "identity_resolution_id": "ligand-1",
    "standardization_artifact": "standardized.json",
    "standardization_record_id": "ligand-1",
    "input_mode": "standardized_smiles"
  },
  "evidence_artifact": "datapro-evidence.json",
  "model": {
    "name": "protenix-v2",
    "version": "not_exposed_by_cli",
    "weights_id": "protenix-v2",
    "seeds": [101],
    "msa_strategy": "none",
    "template_strategy": "none",
    "rna_msa_strategy": "none",
    "dtype": "bf16",
    "samples": 5,
    "steps": 200,
    "cycles": 10
  },
  "covalent_bonds": [],
  "constraint": null
}
```

所有文件路径都必须解析到 `request.json` 所在目录或其子目录。绝对路径只有在
仍位于该目录内时才接受；`..`、父目录 symlink 或其他路径逃逸一律失败关闭。
MSA、模板、配体结构和参考结构必须同时提供 SHA-256。

### 3.1 蛋白质

`proteins` 必须是非空数组。每条链要求：

- `chain_id`：1–4 位英文字母或数字，所有实体全局唯一；
- `sequence`：只允许 20 种标准氨基酸字母与 `X`；
- `organism`：明确物种或 `unknown`；
- `source`：数据库/用户文件、标识符和可选 URL；
- `modifications`：可选，字段原样映射到官方 `proteinChain.modifications`。

多链通过多个对象表达，不用一个对象伪造多条序列。

### 3.2 DNA、RNA、离子和辅因子

可选字段：

- `dna`：`chain_id`、只含 `A/T/G/C/N` 的序列、`organism`、
  `source.database` 和 modifications；
- `rna`：`chain_id`、只含 `A/U/G/C/N` 的序列、`organism`、
  `source.database` 和 modifications；
- `ions`：`chain_id`、不带 `CCD_` 前缀的官方离子 code；
- `cofactors`：`chain_id` 和带 `CCD_` 前缀的 CCD code。

这些对象只映射官方 `dnaSequence`、`rnaSequence`、`ion` 和 `ligand`。

### 3.3 配体

支持三种 `input_mode`：

| 模式 | 进入 Protenix 的值 | 前置要求 |
|---|---|---|
| `standardized_smiles` | 标准化 Artifact 的 `standardized_structure` | 必须有标准化 Artifact；不得用 parent 覆盖 |
| `ccd` | `CCD_<code>` | `confirmation_status` 必须为 `user_confirmed` 或 `expert_confirmed` |
| `structure_file` | `FILE_inputs/<staged file>` | SDF/MOL/MOL2/PDB；文件哈希必须核对；结构标准化 Artifact 必须存在 |

名称或数据库标识符输入时，必须同时提供身份 Artifact。只有
`standardization_handoff.status=ready` 才可自动进入结构标准化。身份未确认时
结果目录保留审计信息，但 Protenix 状态为 `not_run`。

标准化记录状态：

| 上游状态 | 是否允许推理 | 下游最低结论 |
|---|---|---|
| `ready_for_downstream` | 是 | `ready_for_review` |
| `review_required` | 是，但完整传播原因 | `review_required` |
| `rejected` | 否 | `rejected` |
| `parse_status=error` | 否 | `rejected` |
| `standardization_status=not_run/error` | 否 | `rejected` |

输入 Artifact 的原始文件 SHA-256 和上游 `result_fingerprint` 都进入
`ligand_handoff.json`。

身份与标准化 Artifact 还必须通过绑定检查：

- identity handoff 与 standardization record 的 ID 一致；
- identity handoff 结构与标准化 `original_structure` 在固定 RDKit 口径下
  得到同一 canonical isomeric SMILES；
- identity `source_inchikey` 与两边原始结构的完整 InChIKey 一致。

任一检查失败时输出 `artifact_binding.status=mismatch`，并以
`R-UPSTREAM-ARTIFACT-MISMATCH` 阻止推理。上游 Artifact 内部可以记录工具
的真实运行路径，但这些路径不得复制到新结果包。

### 3.4 MSA、模板和参考结构

首版策略：

```text
none
precomputed
```

`precomputed` 时必须提供本地文件和 SHA-256。文件复制到结果目录 `inputs/`，
Protenix JSON 使用相对路径。`auto` 搜索不在本地准备脚本中执行，后续应由
GPU Runtime 明确调用官方 `protenix prep/mt/msa`，并形成独立 Artifact。
蛋白质/RNA MSA 只接受 `.a3m`，模板只接受 `.a3m` 或 `.hhr`，参考结构只
接受 `.pdb`、`.cif` 或 `.mmcif`。
复制前会对 A3M、HHR、SDF、MOL、MOL2、PDB、CIF/mmCIF 和 FASTA 执行
流式 Secret 与主机路径扫描；命中后失败关闭。

PDB/mmCIF 参考文件默认只用于来源记录、盲测或结果对齐，不自动转换为蛋白链。
需要从结构文件构建官方输入时，应在独立 Runtime 显式运行官方
`protenix json` 命令，不能由本 Skill 猜测 assembly、altloc 或缺失残基。

## 4. DataPro 证据 Artifact

DataPro 由宿主 Agent 调用。脚本接受已经保存的 JSON：

- `code`、`msg`、`trace_id`、`dataset_type`、`query`、`total`；
- `items` 中题名、URL、摘要、作者、日期、DOI 和其他原始字段。

脚本不补 DOI、不抓取全文、不根据摘要生成事实。没有 Artifact 时：

```json
{
  "evidence_status": "not_run",
  "source": "dataPro_search",
  "items": []
}
```

`code=0` 且 `dataset_type=academic_search` 只表示检索完成。每个 item 的
全文核验状态默认仍为 `candidate_only`。

## 5. 官方 Protenix 输入

最终 `protenix_input.json` 顶层必须是非空数组（阻断任务除外）。每个任务：

```json
[
  {
    "name": "complex-001",
    "sequences": [
      {
        "proteinChain": {
          "sequence": "MKT...",
          "count": 1,
          "id": ["A"],
          "modifications": []
        }
      },
      {
        "ligand": {
          "ligand": "CCO",
          "count": 1,
          "id": ["L"]
        }
      }
    ],
    "covalent_bonds": []
  }
]
```

只有官方 constraint 模型才允许写 `constraint`。Protenix-v2 当前官方模型表
未声明 constraint 支持，准备脚本必须拒绝把约束静默传给不支持的模型。
当前 Runner 只通过官方 CLI 的 `--model_name` 选择权重，因此
`model.weights_id` 必须与 `model.name` 一致，不能记录一个实际未使用的权重。
只要输入包含 `covalent_bonds` 或 `constraint`，即使运行和文件合同全部通过，
审查结论也必须保持 `review_required`；现有 Validator 只验证字段和结构文件，
不独立断言目标键或软约束已经满足。

### 5.1 GPU Runtime 资产清单

默认运行要求显式提供 `runtime-assets.json`：

```json
{
  "schema_version": "1.0.0",
  "model_name": "protenix-v2",
  "protenix_version": "2.0.0",
  "protenix_root_dir": "/managed/runtime/protenix-data",
  "checkpoint": {
    "name": "model_checkpoint",
    "relative_path": "checkpoint/protenix-v2.pt",
    "sha256": "<64 hex>"
  },
  "required_caches": [
    {
      "name": "ccd_components_file",
      "relative_path": "common/components.cif",
      "sha256": "<64 hex>"
    }
  ]
}
```

实际清单必须包含：

- `ccd_components_file`；
- `ccd_components_rdkit_mol_file`；
- `obsolete_release_data_csv`；
- `pdb_cluster_file`；
- 启用模板时再包含 `obsolete_pdbs_path` 和 `release_dates_path`。

从已安装的 Runtime 确定性生成清单：

```bash
python scripts/build_runtime_assets.py \
  --protenix-root-dir /managed/runtime/protenix-data \
  --model-name protenix_base_default_v1.0.0 \
  --output runtime-assets.json
```

该命令不下载任何资产；任意 checkpoint 或必需缓存缺失、为空或
是 symlink 都会失败关闭。启用模板时追加
`--include-template-caches`。

Runner 校验所有文件存在、非 symlink、位于 `protenix_root_dir`、非空且
SHA-256 匹配，再将 `PROTENIX_ROOT_DIR` 注入子进程。结果只保存相对路径、
大小和哈希，不保存 Runtime 主机路径。

未提供清单时默认 `not_run/ASSETS_MANIFEST_REQUIRED`。只有用户明确确认模型
及缓存下载、网络、磁盘和费用边界后，才允许显式传入 `--allow-download`。

## 6. 结果目录

```text
<result-dir>/
├── inputs/
├── input_manifest.json
├── evidence.json
├── ligand_handoff.json
├── protenix_input.json
├── run_manifest.json
├── protenix_stdout.txt
├── protenix_stderr.txt
├── protenix_output/
│   └── .../predictions/*.cif
│       .../predictions/*_wounresol.cif
│       .../predictions/*_summary_confidence_sample_*.json
│       .../predictions/*_full_data_sample_*.json
├── validation_report.json
└── report.html
```

官方可能额外写出移除 unresolved atoms 的 `_wounresol.cif`。Runner 将它登记为
`auxiliary_structure_files` 并独立解析，但只用不带该后缀的主 CIF 与 summary
confidence 做 job/seed/sample 一一配对。

每个 JSON Artifact 有独立确定性 fingerprint。处理时间、运行时长和自身
fingerprint 不进入哈希。用户原始输入文件、证据和上游 Artifact 均记录
SHA-256。

## 7. 运行状态和失败分类

运行状态：

```text
completed
partial
not_run
error
```

审查结论：

```text
ready_for_review
review_required
rejected
```

失败分类至少包括：

```text
PROTENIX_NOT_INSTALLED
GPU_UNAVAILABLE
UPSTREAM_BLOCKED
ASSETS_MANIFEST_REQUIRED
RUNTIME_ASSETS_INVALID
RUNTIME_VERSION_MISMATCH
TIMEOUT
CANCELED
NONZERO_EXIT
OUTPUT_MISSING
OUTPUT_INVALID
DEPENDENCY_MISSING
```

`completed` 的必要条件：

1. 上游没有阻断；
2. Protenix exit code 为 0；
3. 至少一个官方 CIF/mmCIF；
4. 每个预测至少有 summary confidence；
5. CIF/mmCIF、链和配体合同通过；
6. confidence 数值有限且必需字段存在；
7. 每个请求的 job、seed、sample 都恰好有一份结构和对应的 summary
   confidence，不得缺失、重复或串样；
8. 独立 Validator 最终 `valid=true` 且 `completion_ready=true`。

## 8. 结构与置信度校验

Validator 使用 Gemmi 解析结构：

- 至少一个 model、chain、residue 和 atom；
- 期望链集合与输出链集合完全一致，不得缺链或多出链；
- 蛋白质、DNA 和 RNA 链的残基数及标准残基序列与输入一致；
- 配体链存在；
- SMILES/结构文件模式下，输出配体重原子数和元素组成必须与固定 RDKit
  口径一致；
- CCD 模式至少检查输出 comp ID 与 CCD code；
- 多链/蛋白质–配体任务的 summary confidence 必须包含 `iptm` 和
  chain-pair ipTM 字段；
- pLDDT 必须在 `0–100`，pTM/ipTM 必须在 `0–1`，链对矩阵必须为
  `N×N` 且元素在 `0–1`；ranking score 必须是有限数值；
- 结构与 summary confidence 文件名中的 job、seed、sample key 集合必须
  完全一致，并等于 `run_manifest.model.seeds × samples` 的请求集合。

这些检查只证明文件和输入映射自洽，不证明结构预测正确。

## 9. Secret、路径与进程安全

- 禁止 API Key、Bearer、Authorization、Cookie、Token 和常见凭证模式；
- Artifact 禁止包含 macOS、Linux 或 Windows 用户主目录等主机敏感路径；
- JSON、日志、A3M、HHR、FASTA、SDF、MOL、MOL2、PDB 和 CIF/mmCIF
  均进入安全扫描；
- Runner 使用参数数组，不使用 shell；
- Runner 启动 Protenix 前移除 Key、Token、Authorization、Cookie、Secret、
  Password 和 Credential 类宿主环境变量，只记录移除数量，不记录名称和值；
- 子进程独立进程组，超时或取消先 TERM、后 KILL；
- stdout/stderr 必须脱敏后写入；
- 请求引用的输入文件必须位于 `request.json` 目录内，拒绝绝对路径越界、
  `..`、symlink 和路径逃逸；
- 结果路径必须位于当前结果目录，拒绝 `..`、symlink 和路径逃逸。
- `protenix_input.json`、`evidence.json`、`ligand_handoff.json`、
  `input_manifest.json` 与 `run_manifest.json` 通过确定性 fingerprint/
  SHA-256 相互绑定；Runner 在查找 GPU 和 CLI 前先验证整包完整性。

## 10. 科学解释边界

允许表述：

- “按 Protenix 版本、权重、seed 和这些输入生成了结构假设”；
- “当前预测包的 pLDDT/pTM/ipTM 为……”；
- “多个 seed 在当前参数下得到相近/不相近的构象”；
- “预测接触与已核验实验参考一致/冲突/无法判断”；
- “结果已准备给结构生物学或药物研发人员复核”。

禁止表述：

- “已证明结合”；
- “已确认活性”；
- “可直接用于实验”；
- “具有治疗效果”；
- “高 ipTM 等于高亲和力或实验准确率”；
- “DataPro 摘要已经证明论文结论”；
- “结构预测通过，所以配体形式、质子化或生物学组装一定正确”。

GPU 验收口径必须区分代码合同、外部运行记录和可复验公开产物：

- 本仓库的输入准备、执行适配、验证和离线测试属于代码合同证据；
- 项目验收记录显示，当前版本曾在独立 NVIDIA GPU Runtime 中完成一次
  无 MSA、无模板的蛋白质单链真实预测并通过 Validator；
- 本公开仓库不包含该次 GPU 的原始结果包，因此第三方不能仅凭仓库复验这次
  运行；
- 蛋白质–配体复合物、多链、MSA、模板和科学准确性仍需分别验收。

因此当前允许表述为：

> 工程候选版已完成离线合同测试，并有一次外部 GPU 单链工程链路验证记录；
> 蛋白质–配体复合物和科学准确性尚未完成验收，不能声明生产可用。
